# AI 桌游拟真 v2 实现说明

本文说明仓库当前实现，供开发、审查和验收使用。实际检查、环境和真实模型结果见 [验收记录](ai-game-realism-v2-verification.md)；规则夹具和结构校验不等于真实模型拟真验收。

## 目标与结构

三个玩法共用“可见观察 → 一次结构化决策 → 校验 → 提交动作和记忆”的流程。AI 仍明确标识为 AI 玩家，以桌游朋友的方式回应具体事件、表达克制的情绪、修正判断，并在适当时保持安静。

| 层次 | 主要实现 | 职责 |
| --- | --- | --- |
| 规则 | `engine/v2/GameRuleSet`、各玩法 `RuleSet` | 纯本地状态转换、合法动作、可见信息、胜负和失败恢复 |
| 观察 | `service/ai/v2/ObservationFactory` | 按行动者过滤公开事件、本人私密事实、人设和本局记忆，生成脱离实体的快照 |
| 生成 | `service/ai/v2/AiTurnGenerator` | 调用既有 `AiGrpcClient`，统一生成动作、发言、神态、证据和记忆建议 |
| 调度与提交 | `service/v2/AiTurnCoordinator`、`V2GameService` | 持久工作队列、事务外调用、认领去重、过期结果丢弃、原子提交 |
| 前端 | `V2ActionPanel`、`useGameEngine`、`PlayerGrid`、`GameLogPanel` | 依据服务器能力呈现交互，复用请求身份，展示轻量神态 |

`GameState.data` 保存 `ruleVersion=2`、本局 `archiveId`、规则快照、随机种子和版本信息。当前公共提示词版本为 `social-v2.1`。这些字段用于定位一次对局和诊断变更；历史回放来自已存事件，不依赖再次调用模型复演。

## 已落地玩法

### 谁是卧底

- 支持 4–10 名参赛玩家，卧底数量支持自动或合法范围内手动配置，可选白板；每轮首位发言者轮换。
- 回合包含描述、有限质疑与回应、投票、必要时的最高票并列辩解和复投。票在收齐或截止后同时揭晓；复投仍平则本轮无人出局，连续三轮无人出局结算平局。
- 非白板玩家只知道自己的词，不直接获知自己是平民还是卧底；白板没有词语资料。白板存活至最后两人时独赢，三人存活时尚未获胜。
- 词库按日常、成语、ACG、科技分类保存词义、属性、生活场景和禁用表达。观察只取本人词的资料，不带词对另一侧、词对顺序或多数阵营信息。
- 提示词要求换描述角度、回应刚发生的质疑、把跟风视为弱证据、根据新信息改票。描述与行动经过规则校验，禁止直接泄露本局词语及已收录的别名等禁用表达。
- 自定义词对保存在房间私有配置。出题主持与参赛席位分离，知晓答案的主持不能参加该局；自定义词局不计竞技统计。

### 狼人杀

- 支持 6、9、12 人，以及 `standard`、`guard`、`no_god` 板子。角色构成由服务器明确生成，不允许显示配置与实际发牌不一致。
- 标准板随人数加入预言家、女巫、猎人和白痴；守卫板包含守卫，并按人数加入其他神职。支持女巫自救规则、屠边或屠城、遗言范围和发言时长配置。
- 夜晚按规则处理守护、狼人建议与投刀、查验、药物和死亡技能。每名狼人只有一次私密建议/投刀机会，多数目标生效，平刀使用本局固定随机种子选取。
- 守卫不能连续守同一人；药物库存、女巫可见刀口、自救限制、猎人能否开枪及白痴失去投票权均由规则执行。
- 白天常规发言后有有限定向互动：最多两组问答、总计 60 秒，真人先有 10 秒发起窗口，被问者有 20 秒回答。投票同时揭晓，平票无人出局。
- 死亡身份默认在结算时翻牌；白痴亮牌免死、猎人公开技能等规则事件另行处理。AI 不得把身份声明和推测描述为服务器已经确认的事实。
- 查验、狼队协商、守护记录和可见药物信息仅给有权行动者。普通观察者的夜晚状态不暴露当前私密行动席位或其截止时间；观察令牌也区分公开和本人私密机会。

### 海龟汤

- 内置六道原创版本化题目，按简单、中等、困难各两道组织。题目保存汤面、事实、排除事实、核心因果链、认可解答及两级提示。
- 主持与盲解玩家使用不同观察和提示词。只有内部 `$host` 裁判观察获得本题汤底；AI 队友只有汤面、公开问答和讨论，不能因题目同名而套用旧答案。
- 真人提问或试答先形成 `pendingHost`。主持仅返回与该请求绑定的私有结构化裁决，服务器生成公开短答；主持不能附带公开解释、神态或记忆。
- 裁决区分是、否、不重要、需要澄清、事实未设定、前提错误和暂时无法裁决。复合问题、未知事实及失败恢复不消耗探索次数。语义等价的已确认命题复用裁决，不重复计费；事实 ID 不会成为玩家自动获得整条隐藏事实的通道。
- 探索次数包含正式有效提问、错误试答和提示。默认 12 次，可配置 4–30 次；AI 正式提问累计最多为上限的三分之一，最后两次留给真人。
- 真人行动开启一轮有限 AI 参与，最多两次不同队友贡献，每轮最多一个 AI 正式提问。AI 可以讨论、提问或 `PASS`，不能自行请求提示、提交最终答案或揭底，也不能无限自问自答。
- 次数用完后进入 `FINAL_ANSWER`，保留一次由真人确认的最终解答，无强制倒计时。主动揭底结束为未解出。主持调用失败通过本地 `UNRESOLVED` 归还控制，保留探索和最终解答机会，不泄露汤底。

汤题同时附带 120 条提问语义夹具和 30 条解答夹具。它们用于离线规则测试和后续单独计预算的主持语义验收，不进入真实游戏观察，也不因离线测试通过而视为模型已经理解所有题目。

## 人设、记忆和可见神态

统一玩家提示词位于 `backend/src/main/resources/game-knowledge/social-player-system.txt`，海龟汤主持使用独立的 `turtle-host-system.txt`。玩法资料由各规则集补充，不能绕过当前 `legalActions`。

AI 一次输出以下内容，服务器将它们作为同一决策处理：

- `action` 与 `speech`：发言和实际动作一致，目标来自当前动作允许的候选人。
- `evidenceEventIds`：只能引用该观察实际提供的事件；本人有权查看的私密事件也可作为私有依据。
- `presentation`：情绪、单个动作和 0–3 强度的白名单值。公开神态代表愿意展示的表演，不等于把内部状态直接公开。
- `memoryUpdates`：仅允许自己的信念、关系、情绪、承诺、假设与已用描述维度，不能修改身份、词语、技能资源、胜负或其他玩家记忆。

本局信念保存假设、置信度和证据引用；关系增量有界，情绪需要真实可见事件触发，并按轮次和人设恢复参数衰减。记忆只在动作成功提交后写入，不采用过期或未通过校验的输出。

稳定人设跨玩法复用。已审核通用经验按 `personaId + gameId + GENERAL_V2` 分桶，因此目前属于同一玩法的跨局经验。只有 `reviewStatus=APPROVED` 的 `approvedSummary` 会进入 v2 观察；旧版原始反思、上一局玩家敌友关系和角色秘密不会自动注入新局。管理员可审核或拒绝通用经验，并留下审计记录；结束一局只更新参与计数，不自动批准经验。

前端只显示受认可的一个短神态，例如轻轻点头、稍稍停顿。相同事件在日志和玩家区域共享表达，新阶段或后续中性事件会清理旧提示；不会渲染模型自由书写的动作段落或思维过程。

## 异步运行、幂等和恢复

1. 开局、真人动作或调度时钟在短事务中执行本地规则，建立唯一行动机会，并把过滤后的观察写入 `ai_turn_jobs`。
2. 工作线程在短事务中把 `QUEUED` 认领为 `RUNNING`。模型调用在该事务结束后执行，不持有游戏数据库锁。
3. 模型输出先校验 JSON、动作能力、目标、发言一致性、事件引用、神态白名单、记忆范围、内容安全及玩法约束。首次格式或合法性失败最多修正一次；网络失败和预算耗尽不进行第二次收费重试。
4. 提交时按房间、状态、任务顺序加锁，重新确认任务状态、本局 `archiveId` 和当前 `TurnRequest`。旧局或过期机会的结果标记 `DISCARDED`，不写动作和记忆。
5. 成功动作、记忆和事件原子提交，再准备下一项合法机会。诊断记录在提交后以独立事务保存，保存失败不会卡住对局，因此诊断统计可能缺少个别记录。异常或长时间遗留任务调用玩法自己的 `onAiFailure`，通过本地跳过、保留主持重试等方式恢复。

默认调度周期为 750 毫秒，AI 工作线程默认 4 个、配置范围 1–8 个；遗留 `RUNNING` 任务超过 60 秒进入恢复检查。有效任务键参与生成任务 ID，同一机会不会因重复轮询建立新的模型工作。线程池认领或投递失败会归还并发名额。

单次模型请求最多 45 秒，一次联合决策连同最多一次修正共享 50 秒总预算。实际对局在请求前重新读取持久任务和当前行动窗口，按剩余时间缩短预算并预留 1 秒提交余量；已过期窗口不发起请求，返回时已过期的结果不写入发言或记忆。

状态 GET 只读取可见状态和活动信号，不驱动游戏阶段、不触发模型调用。自动推进由调度器执行。真人动作支持 `requestId` 和 `expectedPhaseToken`：同一请求重复提交返回当前结果，过期令牌产生冲突；前端在未确认的网络重试期间保留请求 ID，成功后才建立新的操作身份。

HTTP 路由判断使用字段投影，不提前将游戏状态放进持久化上下文，避免等待房间锁后继续使用旧状态。海龟汤汤面、提示及已确认且非重复的正式问答会在可见事件过滤后保留，长局讨论不会挤掉这些基础事实。同轮多次动作也不会重复计算情绪恢复。

幂等记录保留最近 256 个已处理请求；旧接口仍可不携带这两个字段，因此不能把旧客户端描述为拥有与新版动作面板完全相同的防重放保证。

## 信息边界和兼容

- 新观察由服务器按行动者过滤，不能把完整 `GameState`、房间私有配置或所有人记忆直接作为提示词发送。
- 公开事件用于广播；私密事件按收件人推送。原始模型输出、内部信念、私密依据和主持汤底不进入普通玩家公开日志。
- v2 对局只在结算后形成回放。`PLAYER` 私密视角绑定已认证用户，不能通过请求参数冒充另一玩家；v2 的 `GOD` 请求按公开视角处理。旧版回放保留旧行为，不能据 v2 改进推断历史接口具有相同权限规则。
- 新开局默认走 v2，`app.game.v2-enabled=false` 可关闭新局入口。已存在的 v2 对局仍由 v2 处理；未完成的旧版对局继续原引擎，不在中途转换规则。
- 原有发言、投票和夜晚操作接口保留，并对 v2 状态转成对应动作；新的动作面板完全依据服务器返回的合法能力显示按钮和目标。
- 侧边交流也受玩法约束：海龟汤文字进入正式讨论，狼人杀/卧底自由文字不能绕过发言轮次；表情和快捷短句有白名单及阶段限制。

## 数据迁移与环境

迁移入口为 [20260912_game_realism_v2.sql](../backend/sql/20260912_game_realism_v2.sql)。它是增量 MySQL 脚本，按列和表是否存在执行，包含：

| 对象 | 变更 |
| --- | --- |
| `rooms` | 增加 `host_user_id`、`private_config`，从旧席位 JSON 回填主持身份 |
| `game_states` | 增加 JPA 乐观锁 `version` |
| `ai_persona_memories` | 增加 `approved_summary`、`review_status`，默认不审核通过 |
| `ai_turn_jobs` | 保存异步机会、观察快照、状态、时间和版本 |
| `ai_call_budgets` | 保存指定验收批次的实际调用预占计数 |

回填使用 MySQL 的 `JSON_TABLE`；应用到目标库前应确认目标数据库支持该语法。脚本不删除旧对局或旧记忆，也不把历史经验自动批准。需要先迁移再在该环境启用新局；回退新局入口时保留增量表和列，以免破坏已存在的 v2 对局与诊断记录。

本地按仓库 Windows 受管启动/停止入口运行。环境发版仍使用 `scripts/ci/build-release.sh`，配置由 config-center 提供。本文记录实现与入口，不构成已经迁移、发版或切换生产域名的证据。

模型选择延续原行为：`APP_AI_DEFAULT_MODEL` 未设置或为空时，`AiGrpcClient` 发送空模型名，由网关选择默认模型；设置非空值时才指定该模型。对照程序不预热模型、不自动切换模型，也不额外调用评审模型。

## 真实对照程序及调用预算

`AiRealismComparisonIntegrationTest` 默认整类跳过。只有显式 `AI_REALISM_COMPARISON=1` 才会启动；需要现有网关地址、HMAC caller/secret、计费系统用户，以及 `AI_REALISM_EVIDENCE_DIR`。模型名可保持空值。证据路径必须是仓库外尚不存在的绝对目录，父目录需要已经存在；程序不覆盖旧证据。

Windows 本地入口为 `scripts/windows/Test-GameRealismV2Comparison.ps1`：

```powershell
./scripts/windows/Test-GameRealismV2Comparison.ps1 -EnvironmentFile '<现有私密env绝对路径>' -EvidenceDirectory '<仓库外新证据目录>' -BudgetFile '<此前一直使用的累计账本绝对路径>' -UseCompiledTests
```

`-BudgetFile` 必填；首次可以创建账本，以后所有重跑必须传入同一路径。若环境已经设置 `AI_REALISM_BUDGET_FILE`，入口拒绝切换成另一份。入口固定使用已获准的普通系统用户 `85` 和 canonical local TLS/HMAC 路线，保留私密 env 的 `APP_AI_DEFAULT_MODEL`，未设置或为空时仍由网关选默认模型。不会导入该文件的数据库认证、登录令牌或其他服务配置，也不修改原文件或持久账户配置。测试使用 H2 和测试 profile，结束后恢复当前进程环境。

`-UseCompiledTests` 只执行 `surefire:test`，先检查本次测试类、主类与资源是否最新；需要已经完成当前版本的后端编译/L2。新增预检等测试修改后，应先刷新测试编译。省略该参数会执行 Maven `test` 生命周期，但仍只选择这一个显式对照测试。为避免原始框架诊断或属性转储包含认证信息，入口抑制 Maven 原始输出及 Surefire XML/正文文件；失败详情使用外部 `preflight.json`、`summary.json` 和已有账本。若编译在测试启动前失败，则不会生成这些文件，应先完成不带真实凭据的离线编译检查。

首个收费请求前使用现有 HMAC 客户端执行一次带 15 秒 deadline 的 `ListModels`，确认目录权限与至少一个 ACTIVE 文本模型。该读取不调用生成模型，不消耗聊天预算，也不重试。预检失败会结束本次收集；成功只说明模型目录可读，不能证明上游余额、默认路由或实际生成正常。客户端现有目录 DTO 没有稳定模型键，因此不会借此自动挑选或替换模型。

对只获准 `aisocialgame/TEXT` 的调用方，显式追加 `-ProjectScopedPreflight`。当前服务的 `ListModels` 请求没有 `project_key`，目录读取会按默认项目检查权限，因此本模式不发目录请求，也不扩大调用方到默认项目。标准本地适配器的传输就绪验证是前提；对照本身不增加健康请求或预热，而把第一个正常情境的 `ChatCompletions(aisocialgame)` 作为真实生成检查，照常预占同一累计账本，失败立即停止。

该模式的初始 `preflight.json` 标记 `SCOPED_GENERATION_PENDING` 和目录不可用于本项目权限；首请求的实际结果位于 `calls.jsonl` 及最终 `summary.json`。仅存在真实非空生成响应且没有调用/账本错误时，摘要才标记 `SCOPED_GENERATION_CONFIRMED`；入口还要求 30 个情境完整收集才视为收集完成。响应失败记录白名单 gRPC 状态、数字 HTTP 状态和有限固定错误分类，不记录任意错误描述或认证内容。默认未传开关时仍保留目录预检。

对照包含三个玩法各 10 个社交情境。旧版狼人杀/卧底调用现有 `AiDecisionService`，新版调用 `AiTurnGenerator`。旧海龟汤实际没有模型，基线调用原引擎的固定问题脚本并标记零模型调用。旧版没有的问答阶段、守卫/猎人/白痴行为明确标记为近似基线，不能按等价玩法对比得分。v2 修订汤题的因果内容与旧脚本也有版本差异。

情境是人工编写的脱离实体快照，包含明确可见事实，不是六场真实房间日志。金标准期望独立保存，绝不附加到模型输入；普通盲解玩家无汤底，单独的主持语义输入才有本题权威事实。输出的结构合法性和引用完整性可自动检查，正式评阅使用用户指定的自然度、回应针对性、人格连续性、情绪与行动一致性四维，各 1–5 分；合作记为证据备注，信息边界独立作为门槛。尺度与逐例证据要求见 `doc/ai-realism-manual-review-rubric.md`，实际评分另外保存为外部 `user-criteria-review.json`，不改写模型原始产物。

调用计数分两层：

- 运行中的 `AiGrpcClient` 使用 `AiCallBudgetService`，在发出请求前以独立事务预占一次预算；格式修正、传输失败都按实际尝试计数。
- 对照程序额外使用仓库外持久账本，所有重跑合计最多 90 次。默认账本为本次证据目录的共同父目录中的 `comparison-call-budget.jsonl`；可用 `AI_REALISM_BUDGET_FILE` 指定固定的绝对文件路径。每次重跑必须继续使用同一个账本，不能更换或删除文件以重置额度。

外部账本对整个对照过程持有文件锁，并在远程请求前写入和强制落盘。即使调用响应丢失、进程终止或单次 evidence 写入失败，该次预占也会保留；日志、鉴权、网络或预算错误会停止后续情境。发现截断或不连续的账本时拒绝自动重置，需要先核对已有预占记录。

理论预算为每个情境旧版最多一次、新版最多两次，硬限 90；由于旧海龟汤是零调用脚本，当前 30 情境实际理论上限为 80。比较账本在独立 H2 测试库之外累计，真实房间使用另一持久预算；计算整体验收最多 300 次时，必须把**对照累计预占数与所有真实房间调用数相加**，保留给六场真实对局的预算不能被重跑重置。

证据包含每次实际请求/响应、模型键、token 数、耗时、降级和错误、情境输入、基线限制及待填写的人工审阅项。`host-semantic-fixtures-not-executed.json` 只导出 150 条汤题语义用例，不发起额外主持调用。证据中可能包含游戏私密信息，应留在验收使用的外部目录，不作为公开回放直接发布。

## 本地只读量化

六局入口为 `scripts/windows/Test-GameRealismV2Live.ps1`：

```powershell
./scripts/windows/Test-GameRealismV2Live.ps1 -TokensFile '<三个账号已完成的私密会话properties>' -EvidenceFile '<仓库外新的六局证据.json>'
```

该入口要求三个不同普通账号，使用正常应用令牌和 `APIRequestContext`；固定 canonical HTTPS 并开启证书验证，不启动浏览器驱动。它检查服务器持久预算，不负责建立账户或重置额度。会话文件由 `Prepare-GameRealismV2Accounts.ps1` 经真实用户登录和既有应用初始化产生，不能用不完整产物替代。

六局脚本留下外部证据后，可运行：

```powershell
./scripts/windows/Measure-GameRealismV2.ps1 -EnvironmentFile '<现有私有环境文件>' -EvidenceFile '<仓库外六局证据.json>' -OutputFile '<仓库外新的量化结果.json>'
```

该入口只使用已有 JDK、Maven 缓存中的 MySQL/Jackson 依赖，不构建或启动服务。数据库路线固定为本地共享 `localbase` 的 `aisocialgame`；私有环境只提供数据库认证，不能改成其他数据库目标。输入证据的 `scenarios[].roomId` 必须是合法 UUID，最多 12 个，不接受重复值。输出文件必须位于仓库外且尚不存在。

查询只读取白名单房间的 trace 数值/模型键/质量标志、任务状态与必要时间，以及固定 `game-realism-v2-live-20260912` 预算行。结果按总计、房间和实际模型汇总生成尝试次数、观察到的 token、降级率、生成耗时均值和最近秩 p95。首轮存在 `QUEUED` 或 `RUNNING` 时，65 秒后再次查询同一任务，记录持续待处理数量与超 60 秒运行数量；这不单独证明任务卡死。没有待处理任务时不会等待第二轮。

公开发言重复率仅使用外部证据中的公开日志，按 AI 任务参与者（包括自动接管，排除主持）及房间分别计算；先按事件 ID 去重，再做 NFKC、大小写、标点空白和简短说话人前缀归一化，忽略少于 10 个字符的文本。它统计同一人的精确重复语句，不代表语义相似度。报告不会输出发言正文、参与者 ID、文本哈希、提示词、原始输出、私密记忆、身份、词语或认证信息。

`quality.calls` 是生成器尝试数，预算拒绝也可能进入其中；固定预算 `consumed` 还包含 AI 起名等本批其他请求。未提交或诊断写入失败的任务可能没有 trace，错误响应的 token 也可能未知，所以报告保留缺失/零用量计数和定义说明，不将 trace 总数当作实际计费总数。空分母与无样本统计使用 `null`。

- 决策仍共享 50 秒总预算，每次 RPC 上限 45 秒；修正剩余不足 5 秒时不再发起。单个 JSON Markdown 围栏可无额外请求地解析，但拒绝尾随第二个 JSON。修正输入包括失败标记和前次结果，最多一次。
