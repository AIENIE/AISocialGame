## 方法及范围

三个专项审计并行开展，主审计者交叉检查关键发现的源码、调用链及适用条件。采用 CodeGraph 符号与调用关系分析、精确源码检索、配置/SQL/脚本审查、依赖公告检查和本地验证。不以文件长度、关键词命中或依赖扫描严重级别直接判定实际可利用性。

工作区初始存在大量未提交改动，因此保持原有业务源码。本轮交付集中在本目录；构建、测试与索引操作另会产生忽略目录内的本地生成物。没有执行漏洞修复、部署、线上攻击、真实付费 AI 调用或数据库迁移。

覆盖对象包括 React/TypeScript 前端、Spring Boot 后端、游戏规则及 AI 任务链、数据库 schema/升级 SQL、Windows 本地入口与 CI/发版脚本。`evidence/source-manifest.json` 留存 540 个实现、SQL 与脚本文件的 SHA-256 指纹（后端 331、前端 144、脚本 65）；这是基线追踪清单，**不表示每个文件都做了逐行审计**。依赖锁、构建配置、测试与文档另按具体问题查阅。

审计遵循仓库 `AGENTS.md`、`aienie-dev-workflow` 及 `security-review` 技能；公共服务集成边界按 `aienie-integration` 及本地权威契约核查。系统矩阵校验通过，不据此推断现网网关、TLS、容量或部署形态已通过验收。

## 整改优先顺序

本轮记录 23 个审计条目：安全 8 项（高 3、中 5），性能及稳定性 10 项（P1 4、P2 6），可维护性 5 项（P1 2、P2 3）。性能 P1 中的 Nginx 项仅适用于流量经过仓库所附代理配置的部署路径。

1. **先闭合身份与消息授权边界**：限制 STOMP 订阅和发布目的地，绑定本地令牌与其原始 SSO 会话，落实服务端注销。
2. **阻止故障放大**：为所有上游调用设置有效截止时间及取消机制，将 AI 调用移出房间行锁事务，避免单个房间阻塞全局调度。
3. **完成成本与发布门禁**：统一 AI 调用前的额度准入和结算，补齐旧库升级 SQL 清单，并让类型检查确实覆盖应用源码。
4. **消除增长和恢复风险**：将回放过滤下推数据库，验证断线重连补同步与并发结算，隔离本地模拟数据和存储异常。

具体编号、严重程度、触发条件、证据行号、修复建议与验收条件见各专项报告。跨方向相关项属于同一整改链时应一起实施，不应把三个报告的条目数量简单当作独立漏洞数量。

## 结论边界

当前已发现需要优先处理的授权、会话及运行稳定性问题。建议先关闭各报告中的高优先级问题，再针对 STOMP 越权、会话撤销、上游超时、慢房间隔离和旧库升级开展有针对性的复验。已有正向防护或单元测试通过，不能代替这些边界的专门验证。

本轮标准 L2 入口退出 0：后端 524 项通过、26 项外部测试跳过，前端 58 项通过；额外应用类型检查重试通过，lint 为 0 错误、110 警告。详细执行范围及一次类型检查异常退出见验证记录。

静态审计未发现某类漏洞不等于证明该类漏洞不存在。本轮没有测量线上吞吐、P95/P99、真实 MySQL 锁等待或公网漏洞可利用性；条件性部署问题以报告所述前提为准。
